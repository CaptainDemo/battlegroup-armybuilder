## 文件与兼容边界

1. 定义明确带格式版本的单军表和全库备份外壳，主数据为玩家选择及精确目录引用。文档格式、外壳格式、数据库结构、规则版本分别管理，费用与派生组成从评估重建。沿用 M09 原始 RosterDocument 恢复 JSON 作为可导入的旧输入。测试或文件中的摘要不能取代真实计算。
2. 导出单份时读取当前内存草稿，即使尚未保存或保存失败也可导出。全库备份包含持久记录及不支持的原稿，并合并当前内存草稿，使用对应记录的最新内存选择。删除标记不作为有效军表导出。
3. 在解析／递归验证前先检查文件字节大小，解析后检查嵌套深度、记录数、单军表购买数和选项目标数量。为这批实现采用明确可测试的上限并在 UI／文档说明，建议单份 2 MiB、全库 20 MiB、最多 200 份、每份 5000 条购买、嵌套深度 64。允许基于真实模型调整数值，但须记录理由，避免无界 JSON.parse 后才执行体积门槛。
4. 先解析、结构／引用检查、兼容分类和预览，再确认写入。预览阶段不修改数据库或当前编辑会话。预览包含名称、精确目录版本、兼容／错误信息、导入数量和写入方式。
5. 默认生成新军表 ID 及新编辑 revision，保留玩家成员／附件身份、挂载路径、选项目标、设置、备注及精确目录版本。跨军表可保留内部 selectionId，不能按名称／数组位置重建引用。
6. 已支持的目录按精确版本解析。不支持的格式或缺失目录需要区分于损坏结构／跨体系引用。可恢复但不支持的输入按原稿保存并可原样下载，不能进入正常评估或被转为当前 Classic 数据。损坏 JSON、同一文档内跨体系／跨版本引用、孤儿及循环等错误输入不得进入正常军表库。未知版本只声明为原稿，不能猜测其语义。
7. 文件内 URL、路径、HTML 和命令均作为不可信数据，目录只从应用索引加载，文本按 React 文本呈现。实际导入保留 known／unknown／not_applicable 等状态。
8. 这轮交付精确版本的文件迁移与恢复。目录 1.0.0／1.1.0 均保持自身含义，游戏数据升级／型号映射对比属于独立用例。

## 写入一致性与玩家流程

- 明确区分新建复制和覆盖现有军表。覆盖必须由用户显式选择目标，以当前存储版本为 expectedRevision，在事务内核对。外壳携带的数据库版本不能作为本地覆盖权限。
- 覆盖与现有自动保存队列在同一军表上有清晰交接，处理在途／待存写入和多标签页更新，避免旧草稿在覆盖后写回。成功后同步当前会话和精确目录，重置相关旧历史，失败保留原军表和当前内存草稿。
- 全库导入需事务化提交，避免后一份失败导致前一份已写入的半完成状态。若混合正常记录与恢复原稿，需在同一导入操作中明确它们的保存方式与结果。新增存储接口时保留 save／remove 的既有并发保证和幂等语义。
- 保存违规草稿、宽松购买及问题面板中的事后规则检查继续可用。购买列表中已移除的预先警告不重新引入。
- 单军表导出、全库备份、文件选择、预览、确认／取消、错误反馈和覆盖冲突均需网页可达，桌面与小屏可操作。正式导入不依赖用户编辑 JSON 或开发者工具。

- 单份导出再复制导入后，成员／层级／目标／设置／备注／目录版本一致，实际评估 Points／BR 一致，身份变化符合默认复制约定。

- 取消预览无写入；超限、损坏 JSON、非法引用和跨体系混合不会进入编辑器。
