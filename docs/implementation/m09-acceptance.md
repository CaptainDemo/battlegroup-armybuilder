# M09 本地保存与恢复验收

日期为 2026-11-07。

## 实现

- Web 存储端口位于 `apps/web/src/adapters/storage/rosterStore.ts`。Dexie 4.4.7 管理当前浏览器来源下的 IndexedDB 数据库，多份军表分别保存选择、精确目录引用、存储版本、时间与可重建摘要。
- 数据库版本 1 定义军表记录，版本 2 增加摘要与删除标记。升级过程中保留原始文档及其目录版本。不支持格式的记录保留原稿并提供恢复下载。
- `saveQueue.ts` 对每份军表串行写入，并合并尚未开始写入的编辑。保存结果只确认对应编辑快照。撤销和重做产生新编辑版本，并推进数据库存储版本。
- 保存和删除在同一读写事务中比较 expectedRevision。不同标签页竞争写入时，一份成功，其余返回冲突。冲突后保留内存草稿，提供载入已保存版本及另存副本。删除留下带新存储版本的标记，阻止旧标签页恢复已删除记录。
- 存储读取或写入失败后可继续编辑，界面保留失败状态并提供重试。失败或冲突草稿可下载原始 JSON。该下载用于恢复，M10 的正式导入与备份外壳另行实现。
- 恢复前验证文档结构和引用，并加载应用索引中的精确目录版本。恢复后的撤销栈从空开始。刷新编辑器路由后，从“我的军表”重新打开记录。

## 验证

294 项单测、类型检查、生产构建及 7 项 Chrome 回归通过。其中 12 项新增检查覆盖保存队列、数据库事务／迁移和恢复边界。数据库测试使用 fake-indexeddb 6.2.7，浏览器验收使用系统 Chrome 的真实 IndexedDB。

真实浏览器流程使用 Playwright CLI 的专用测试会话执行。

| 场景 | 观察结果 |
|---|---|
| 保存违规草稿 | 仍可保存超分军表，恢复后费用与违规结果一致 |
| Chrome 关闭重开 | 独立持久化配置的 Chrome 进程关闭后重新启动。320 Points 的 BMP-1 连、三个固定排、已购附件和四个 BMP 升级目标完整恢复。逐字段比较文档一致 |
| 快速编辑与历史 | 连续五次添加后保存最新七条购买。撤销／重做后的存储版本依次为 9、10、11，购买数为 7、6、7 |
| 旧保存完成 | 控制异步保存顺序的队列测试确认旧快照完成时，新快照仍显示保存中 |
| 写入失败 | 模拟 QuotaExceededError 后仍可继续购买并下载最新内存草稿，恢复写入后重试成功 |
| 首次读取失败 | 模拟 IndexedDB 打开失败后仍可新建和编辑。恢复打开权限并重试，原有列表与内存草稿均可恢复保存 |
| 双标签页竞争 | 先写标签页保存成功，后写标签页显示冲突并保留名称和选择。另存副本及载入远端版本可用 |
| 删除与旧标签页 | 删除提交后，旧标签页的编辑返回冲突。重新载入确认删除，关闭重开也不会恢复被删除记录 |
| 版本锁定 | 1.0.0 军表以原目录恢复，仍为 398 Points／23 BR |
| 不支持格式 | 原稿进入恢复条目，下载后与输入对象一致 |
| 数据库迁移 | 浏览器真实 IndexedDB 版本 1 升至 2，原稿及 saveRevision 保留 |
| 小屏 | 360px 视口显示恢复后的军表，无横向溢出 |

本地证据保存在 Git 忽略的 `.tmp/soviet-v41/m09-*.log` 与对应检查 JSON 中。最初的浏览器脚本在刷新 `#/editor` 后直接寻找军表列表而超时，改为通过“我的军表”打开记录后通过。该失败日志保留。

构建主脚本为 509.02 kB，gzip 后为 152.51 kB。Vite 提示主块超过默认 500 kB 阈值，构建正常完成。

## 使用边界

数据保存在同一浏览器配置、同一来源下。页面显示“Saved locally”后可关闭，保存失败和冲突时可下载内存原稿。此阶段恢复军表选择和版本，编辑器选中行及撤销历史属于当前会话状态。跨来源迁移和完整备份导入由 M10 交付。
